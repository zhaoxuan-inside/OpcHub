# 后端编排功能重构 · 三层资产目录与排他锁 — 验收审计（2026-10-25）

## 需求原文

> 后端编排功能重构：
> 1. 算子展示，创建，删除，版本管理，发布；
> 2. 子图展示，创建，编排算子，版本管理，发布；
> 3. 场景展示，创建，删除，版本管理，算子和子图编排，发布；
>
> 展示功能没有限制；其他功能都需要解锁才能进行操作，避免多人同时操作导致业务异常；要显示锁定的状态和锁定人。

## 交付范围

| 模块 | 说明 |

### 前端（ConsoleView 重写为三层工作台）

- 三页签：算子（预置/自建、版本、发布、删除、脚本编辑）/ 子图（画布编排、版本、发布）/ 场景（算子+子图画布编排、发布、执行、删除；系统预置管线只读展示）

## 验收结论

### 自动化（backend/tests/test_orchestration_catalog.py，15 例全过）

- 锁：获取 / 冲突展示锁定人 / 心跳续期 / 过期接管 / 非持有人释放拒绝 / 管理员强制释放 / 锁看板公开
- 权限：四类目录读无凭证可访问；写未登录 401、普通创客 403、管理员未持锁 403（提示先锁定）
- 算子：创建（危险脚本被沙箱拒绝）→ 发布注册进算子池 → 已发布版本不可编辑 → 新版本发布旧版 SUPERSEDED → 删除（引用保护 / 预置算子不可删除）
- 子图：创建 → 编排 → 发布编译；环 / 多入口 / 引用未发布算子均拒绝
- 场景：混合编排 → 发布（子图内联 `guard::` 前缀展开、物化 ACTIVE、旧版 SUPERSEDED）→ 执行走最新版 → 删除清理运行时配置
- 回归：管线缺失时首个写调用自愈（懒加载场景）
- 全量回归：455 passed / 5 skipped / 2 failed（`test_versioned_hot_reload` 两例为既有基线失败，与本次无关）

### 浏览器端到端（真实 GUI 操作）

在隔离栈（vite dev 3100 → 内存态后端 8017，管理员首登改密流程走通）：

1. 子图 SG_BROWSER_ACCEPT：新建（自动锁定）→ 画布加 auth_guard / invoice_tax_calc → 连线 → 保存 → 发布 ✅
2. 场景 OPC_BROWSER_ACCEPT：新建 → 画布加 gateway_ingress + 子图 + es_audit_sync → 连线 → 保存 → 发布 ✅（首次发布被校验拒绝：出口节点不唯一 —— 校验生效，修复画布出口推断 bug 后通过）
3. 执行：4 节点全部 SUCCESS，子图内联为 `guard::auth / guard::tax` ✅
4. 锁定展示：全局锁看板显示「子图 SG_BROWSER_ACCEPT · 平台超级管理员 · 剩 N 分」；列表行 🔒 锁定人；编辑面板「我持有编辑权 / 已被锁定（含锁定人）/ 空闲」三态 ✅
5. 删除与清理：API 删除场景（连同运行时版本）、锁全部释放、无残留 ✅

### 用户栈修复（工作台不可用问题）

根因：8000 端口开发后端仍运行旧代码（无 `orchestration.catalog.*` 路由），而 3000 端口伺服的 dist 已是新工作台，全部目录调用 404。处置：重建 dist 并重启 8000 后端加载新代码；经 3000 代理回归验证（算子 116 / 场景 36 / 目录读全通）。

### 过程中发现并修复的缺陷

1. **元管线懒加载缺口**（P0）：管线种子原挂在 catalog 模块导入副作用，全新实例首个调用若是写操作则管线不存在 → 抽取幂等 `ensure_catalog_pipeline` 并由写适配器显式调用，附回归测试
2. **画布出口推断**：链式追加节点时出口未后移导致发布被拒 → 改为追加即后移
3. **面板资产过期**：子图/场景面板的可编排清单只在挂载时加载，跨面板发布后不可见 → 选中资产时刷新
4. **错误文案透出引擎内部串**：校验消息中文化并剥离 `Node step_persist execution error:` 等前缀

### 文案治理（非业务内容清理）

工作台头部架构说明段移除，替换为一句话业务描述；扫除实现术语：沙箱/四防火墙 → 安全校验、排他锁 → 编辑锁/锁定、心跳续期 → （删除）、编译部署/ACTIVE → 发布并即时生效/使用中、运行时内置管线 → 系统预置、内置 → 预置、拓扑 → 编排/连线、Saga → 失败时自动回滚。

## 追加迭代（2026-10-25 第二轮）

1. **预置算子版本号**：目录中预置（代码注册）算子统一以平台版本 `v1.0.0` 标识（`BUILTIN_OPERATOR_VERSION`，合成的 PUBLISHED 版本行，更新说明“平台预置版本”），列表“当前版本”列不再显示"—"
2. **列宽自适应**：算子/子图/场景三张列表由固定比例 grid 改为真表格布局（`table-layout: auto`），列宽随内容自动调整；名称列限宽换行，超宽时卡片内横向滚动，操作列右对齐
3. **算子使用状态**：`OperatorAsset` 新增 `in_use` / `referenced_by`（读取时实时计算，不入持久化快照）；列表新增“使用状态”列（使用中/未使用，悬停显示引用方），详情面板展示引用明细。统计口径（第三轮修正）：已发布子图版本 + 已发布场景版本 + **正在运行的系统预置流程（ACTIVE 运行时配置，管理场景物化的配置去重不计）**——首轮只统计管理目录导致全部预置算子误显示“未使用”；修正后 116 个算子 95 使用中 / 21 未使用（旧别名与未被任何运行流程引用的外部算子）

验证：`test_operator_builtin_version_and_usage` 新增（预置 v1.0.0、发布引用后 in_use 联动与引用方展示），目录测试 16 例全过；全量 456 passed / 2 既有基线失败；浏览器回归确认三张表格列宽自适应、v1.0.0 与使用状态列正常渲染。
